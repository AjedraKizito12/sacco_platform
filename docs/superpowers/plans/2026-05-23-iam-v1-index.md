## What Each Plan Delivers

### 01 · JWT Infrastructure
`app/modules/iam/keys/` — crypto.py, models.py, service.py, schemas.py, api.py
`app/modules/iam/tokens/service.py`
Platform migration `003_iam_platform.py` — `platform.jwt_signing_keys`
`GET /.well-known/jwks.json`
Celery beat tasks: `rotate_signing_keys_if_due`, `advance_key_lifecycle`
Config additions: `JWT_KEK`, `JWT_KEY_ROTATION_DAYS`, token TTL settings

### 02 · Password Hashing
`app/modules/iam/passwords/service.py` — hash, verify, needs_rehash
Config: `AUTH_PASSWORD_MIN_LENGTH`

### 03 · Sessions
`app/modules/iam/sessions/models.py` — PlatformSession, TenantSession
`app/modules/iam/sessions/service.py` — create, get, revoke, cleanup
Platform migration `003` extended: `platform.platform_sessions`
Tenant migration `001_iam_tenant.py`: `tenant_sessions`
Redis caching layer for hot-path session validation

### 04 · Tenant Users
`app/modules/iam/tenant_users/models.py` — TenantUser
`app/modules/iam/tenant_users/service.py` — create, get, list, update
Tenant migration `001` extended: `tenant_users`
`app/platform_/provisioning/steps.py` — seed_defaults extended with admin_email bootstrap

### 05 · Platform Auth Endpoints
`app/modules/iam/platform_auth/schemas.py`, `service.py`, `api.py`
`POST /platform/auth/token` — full login flow
`POST /platform/auth/refresh`
`POST /platform/auth/logout`

### 06 · Tenant Auth Endpoints
`app/modules/iam/tenant_auth/schemas.py`, `service.py`, `api.py`
`POST /auth/token`, `/refresh`, `/logout` (mirrors platform, uses X-Tenant-Slug)

### 07 · /me Endpoints
`GET /platform/auth/me` — PlatformUserOut
`GET /auth/me` — TenantUserOut

### 08 · Password Reset
Platform and tenant: `POST /*/auth/password-reset/request` + `confirm`
HMAC-signed reset token, Redis jti store, 15-minute expiry
Pluggable notifier interface (log-to-structlog default, email future)

### 09 · Dependency Swap
`app/modules/iam/dependencies.py` — JWT implementations
`app/platform_/auth.py` — import-time binding switch (`PLATFORM_AUTH_MODE`)
Introduces `TENANT_AUTH_MODE` equivalent for tenant routes
All existing callers of `get_current_platform_user` continue unchanged

### 10 · Lockout
`app/modules/iam/lockout.py` — record_attempt, is_locked, reset
Wired into platform and tenant login paths
Config: `AUTH_LOCKOUT_THRESHOLD`, `AUTH_LOCKOUT_WINDOW_MINUTES`, `AUTH_LOCKOUT_DURATION_MINUTES`

### 11 · Auth Audit
All 14 audit event types wired throughout auth services
`iam.key_rotated`, `iam.key_lifecycle_advanced` via KeyService

### 12 · Boot Check Flip
`APP_ENV=production` + `PLATFORM_AUTH_MODE=stub` → startup refusal (already half-done; this plan completes it for `TENANT_AUTH_MODE`)
`JWT_KEK` validation on settings load
`verify_boot_keys()` called in lifespan
CLAUDE.md IAM contracts section added
`.env.example` complete with all new vars
